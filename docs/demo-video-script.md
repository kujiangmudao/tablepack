# Demo video script（README GIF + 3 分钟演示）

> 一次录制产出两份素材：README 循环 GIF + 3~5 分钟产品演示（可用于竞赛演示视频与面试）。
> 录制原则：只演示 `examples/demo` 的合成数据；真实语料一律不上镜（或只给脱敏截图）。

## A. README 用 GIF（15~20 秒，循环友好）

准备：干净仓库一份，`pdf/` 里放 `examples/demo/demo_sample.pdf`；终端字号 ≥16。

| # | 镜头 | 建议字幕 |
|---|------|----------|
| 1 | 终端运行 `python -m pdf_excel --import-db`（MinerU 日志滚动 2~3 秒） | 一条命令 |
| 2 | 打开 `output/demo_sample/`：xlsx + `原始表格/` + 说明 + `.db` | 可核对的交付包 |
| 3 | Excel：工作簿多 sheet，表格网格 | 一表一 sheet |
| 4 | 截图（crop）与对应 sheet 并排 | 自带质检截图 |
| 5 | `sqlite3 output/demo_sample/demo_sample.db ".tables"` + 一条 `SELECT` | 可查询的数据资产 |

导出：真实素材压到 15~20 秒以内，首尾衔接可循环；另存 `docs/assets/demo.gif`。

## B. 3 分钟演示（竞赛 / 面试通用）

| 时间 | 画面 | 口播要点 |
|------|------|----------|
| 0:00–0:20 | 标题页 / 痛点示意 | 论文与报告里的表格：手工抄 Excel，格式乱、无法核对、无法入库 |
| 0:20–0:50 | 架构一页图（PDF → 解析 → 交付包 → 数据库） | 不是"再写一个转换脚本"，而是把最后一公里封成一条命令，并把可核对与数据资产化一起做进去 |
| 0:50–1:40 | 实机录屏：放 PDF → 一条命令 → 交付包 | 边跑边讲：一个 PDF 一个 Excel，一表一 sheet |
| 1:40–2:20 | 三个差异化展示 ① `原始表格/` 截图核对 ② 空表写进说明、绝不编造 ③ `--import-db` 入库（类型推断 / `_src_*` 溯源 / 去重计数） | 打开 excel、crop、`.db` 查询三条线 |
| 2:20–2:50 | 批量场景：多份 PDF → `--warehouse` 共享数据库 | 跨文档查询一句话演示：`SELECT * FROM "某文档__表1" ...` |
| 2:50–3:00 | 尾页：开源地址 / star 数 / Agent Skill | Call to action：GitHub 搜索 tablepack |

## 录制技巧

1. 1920×1080，鼠标动作放慢 1.5 倍节奏；提前把命令写好，避免打字卡顿
2. 演示 `--import-db` 与 `--warehouse` 时，先跑一遍暖缓存，录制时只展示关键输出
3. B 版视频剪两支：3 分钟完整版 + 60 秒剪短版（投递用）
4. 旁白用普通话，语速放慢；字幕务必带（评委可能静音看）
